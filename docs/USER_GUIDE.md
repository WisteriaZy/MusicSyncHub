## 1. 这个工具是干什么的

Music Sync Hub 是一个**跑在你电脑上的音乐库管理工具**。它把每一个"放音乐的地方"登记成一个**数据源**——
可以是本机的一块硬盘、一个 U 盘、一个已经映射成盘符的共享文件夹，也可以是一个网络地址——
然后把这些位置里的音频文件读成一份**索引**，让你在一个界面里同时看几个库、比它们、查重复、把文件安全地在它们之间搬来搬去。

它解决的核心问题是：两个库里的**元数据写法经常不一样**（一边有音轨号前缀、一边没有；标签语言不同）。
所以它的匹配不靠"标签是否一致"，而是靠**文件名 + 时长 + 内容哈希**这本账。
于是你能看到"左边这首歌右边到底有没有""右边那份音质是不是更好""哪几个文件其实是同一份东西的拷贝"，
并且所有会改动磁盘的动作都排在你自己手上——**工具不会替你做决定，更不会自动删东西**。

它**不是**什么：

- **不是播放器软件。** 界面里确实能试听（点 ▶ 就在浏览器里播了，能拖进度条），但那是为了"让我听一下这两份到底是不是同一个版本"。
  它没有歌单管理、没有均衡器、没有歌词、没有媒体库刮削，也不替代你的日常播放器。
- **不是通用文件管理器。** 它只把音频文件当作"曲目"来管理。`.cue`、`.nfo`、`.jpg`、`.txt`、压缩包这些**不会**出现在曲库浏览和文件浏览的列表里，
  唯一的例外是几个地方会**列出来提醒你它们占着磁盘**（见第 8、13 章）。
- **不是自动整理机器人。** 整理、查重、搬运都要你点"看方案 → 预演 → 执行"，而且默认策略一律是"目标存在就跳过"，不会覆盖。

## 2. 安装

### 2.1 需要什么

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows（本手册按 Windows 界面写） | 项目也带了 macOS / Linux 的启动脚本，但磁盘类型识别、便携设备探测只在 Windows 上实现 |
| Python | **3.12 或更高** | `pyproject.toml` 里声明 `requires-python = ">=3.12"`；打包好的 `.venv` 内置的是 CPython 3.13.11 |
| 浏览器 | 任意现代浏览器 | 界面是纯 HTML/CSS/JS，不依赖任何外部 CDN，完全离线 |
| 其它软件 | **不需要** | 不需要 ffmpeg、不需要数据库服务、不需要转码工具 |

### 2.2 两种安装方式

**方式 A：用 `uv` 装（推荐，环境干净、可以复现）**

1. 安装 [uv](https://docs.astral.sh/uv/)。Windows 上在 PowerShell 里执行：
   ```powershell
   powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
   ```
2. 进入项目目录，执行一次：
   ```powershell
   uv sync
   ```
   它会在项目目录里建 `.venv\` 并装好全部依赖（见 2.3）。第一次需要联网，之后不需要。
3. 双击 `start.bat`（或者命令行 `start.bat 0.0.0.0 9000` 换监听地址/端口）。

**方式 B：直接用打包好的 `.venv`**

项目里已经带了一个完整的 `.venv\`（内含 Python 3.13.11 与全部依赖）。
这种情况下**什么都不用装、也不用联网**：

1. 双击项目根目录的 `start.bat`；
2. 看到黑窗口里打印 `界面地址： http://127.0.0.1:8787` 就可以打开浏览器了。

> 想把整个工具搬到另一台 Windows 机器上，把项目目录整体拷过去即可（`.venv` 里是 Windows 版解释器，拷到 Windows 上能直接用）。

### 2.3 依赖清单（由 `pyproject.toml` 确认）

| 依赖 | 用户能感知到的用途 |
| --- | --- |
| `fastapi` + `uvicorn[standard]` | 本机 Web 服务（也就是你访问的那个界面） |
| `mutagen` | **读/写音频标签**。没有它就没有标题/作者/专辑，也没有"编辑标签" |
| `Pillow` | 封面图缩放与缩略图。缺了只是封面不缩放，其它不受影响 |
| `httpx` | WebDAV / HTTP 目录两种数据源 |
| `paramiko` | SFTP 数据源 |
| `smbprotocol` | SMB / Windows 共享数据源 |
| `python-multipart` | 上传文件（浏览器表单） |

装有 `mutagen` 与 `Pillow` 的状态会显示在「设置 → 运行环境」里（`mutagen 可用` / `Pillow 可用`）。

### 2.4 `start.bat` 到底做了什么

按顺序：

1. `cd /d "%~dp0"`——切到脚本自己所在的目录（所以从任何地方双击都能跑）。
2. 读两个参数：`start.bat [host] [port]`，默认 `127.0.0.1` 与 `8787`。想让同局域网的手机/另一台电脑访问，用 `start.bat 0.0.0.0 8787`。
3. 找 `.venv\Scripts\python.exe`。**找不到**时会去调 `uv sync` 现场装依赖；连 `uv` 都没有就报错退出并提示你先装 uv。
4. 设 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`（避免中文路径/中文输出乱码）。
5. 打印界面地址、数据目录（`%USERPROFILE%\.music-sync-hub`）、以及"按 Ctrl+C 停止"。
6. 启动 `python -m app.main --host ... --port ...`。如果服务异常退出（退出码非 0），窗口会 `pause` 停住，方便你看上面的报错。

停止服务：在那个黑窗口里按 `Ctrl+C`。重启：再双击一次 `start.bat`，**索引不会丢**。

## 3. 第一次使用

从零到"能听歌"最短的一条路，一共 5 步，界面上按钮名都写在这里了。

**第 1 步：添加数据源**

打开界面（默认 `http://127.0.0.1:8787`）。默认停在 **「数据源」** 页，点工具栏的 **「添加数据源」**
（左侧导航窗格底部也有一个同名的 **「添加数据源」**）。

在弹出的对话框里填：

- **名称**：随便起，比如 `Windows 音乐库`；
- **唯一 ID**：一个短标识，比如 `win`（添加后不可改）；
- **类型**：默认就是 **本地 / 已挂载盘符**；
- **本地根路径**：比如 `D:\Music`。不确定路径就点右边的 **「选磁盘」**，从这台机器的盘里挑。

填完点 **「添加」**。

**第 2 步：测试连接**

鼠标移到刚才那块磁贴上，右上角会浮出一排图标按钮，点 **🔌（测试连接）**。
成功时会显示"连接成功（xx ms）／根目录 N 项：X 个文件夹 / Y 个音频文件"，并列出几个文件名。
如果路径写错了，这里会直接告诉你（比如"路径不存在"）。

**第 3 步：扫描建索引**

还是磁贴右上角，点 **⟳（扫描建索引）** → 确认框里点 **「开始扫描」**。
扫描对话框里可以：限定"只扫描子目录"、改并发线程数、勾"扫描时顺带计算抽样哈希"。
点 **「开始扫描」** 后，进度显示在**右上角的任务条**里，扫完会弹一句
"扫描完成：N 个文件，解析 X，缓存命中 Y，失败 Z"。

**第 4 步：浏览**

点顶部 **「曲库浏览」**，左上角下拉选你刚加的数据源。
你会看到封面、文件名、作者、专辑、时长、体积等列；统计卡上给出曲目总数、总体积、平均码率、无损占比、总时长。

**第 5 步：试听**

点任意一行右侧的 **▶**，底部播放条开始播（可以拖进度条，可以调音量）。
双击一行是"从这首开始，把当前列表放进队列"——这样"下一首/上一首"才真的有内容。

> 到这一步就算通了。接下来想做的事，直接跳到你关心的那一章：
> 想比对两个库看 [双栏对比](#10-双栏对比与同步)；想清理重复看 [查重](#11-查重)；
> 想把乱放的歌归类看 [智能整理](#12-智能整理)；想把散装文件加进库看 [上传入库](#9-上传入库)。

## 4. 界面导览

顶部是 8 个标签页，左边是可折叠的导航窗格，底部是常驻播放条。

| 标签页 | 一句话定位 | 最常用的操作 |
| --- | --- | --- |
| **数据源** | 管理"音乐放在哪" | 添加 / 编辑 / 测试连接 / 扫描 / 浏览目录 / 删除 |
| **曲库浏览** | 按"歌"看 | 搜索、排序、筛选、试听、看详情、导出 CSV |
| **文件浏览** | 按"文件夹"看 | 新建/改名/移动文件夹、批量移动、编辑标签、删除到回收站、跨库传输、上传入库、智能整理 |
| **中转站** | 放"还没想好放哪"的文件 | 归入目录、智能分配去向、还原原位置、移入回收站、清理暂存区 |
| **双栏对比** | 两个库并排看差异 | 开始对比、看配对详情、生成同步计划、预演、执行 |
| **查重** | 找重复并清理 | 选范围、开始查重、选保留哪份、生成清理计划 |
| **操作记录** | 我做过什么 / 正在做什么 | 看任务进度、暂停/取消、接着做完、查看逐文件明细 |
| **设置** | 参数与运行环境 | 改算法参数、看日志、看索引统计、清界面偏好 |

### 4.1 顶栏

- 左上 **☰**：显示/隐藏左侧导航窗格（也可以按 `Ctrl+B`）。
- 右侧 **系统状态徽标**：显示"N 源 · 索引 X MB"；如果依赖缺失，会直接写 **缺 mutagen** / **缺 Pillow**。
- 右侧 **任务进度条**（有任务时才出现，如"扫描中"）：点它可以打开任务中心。
- 右侧 **「重载配置」**：重新读取 `config.toml`。手工改过配置文件后用这个，不用重启。

### 4.2 左侧导航窗格

上半部分是**数据源列表**（带在线/离线小圆点和曲目数），底部是 **「添加数据源」**；
下半部分是**目录树**，点数据源后展开，用于在曲库浏览/文件浏览里快速跳到某个文件夹。

### 4.3 底部播放条

现在播放的封面与标题、**上一首 / 播放暂停 / 下一首**、进度条与时间、音量、
**随机播放（S）**、**循环：关 → 队列 → 单曲（L）**、**播放队列（Q）**。
播放条右侧还有一个徽标，显示"当前在播的是哪个数据源 · 音质标签"（例如 `Windows 音乐库 · 无损 44.1k`），
方便你随时确认"我听的到底是哪一份"。试听是流式的（服务端支持 Range），所以能直接拖进度条。

#### "播放"和"加入播放列表"是两件事

| 你点哪里 | 会发生什么 |
| --- | --- |
| 曲库行首的 ▶ / 双击某一行 | **只播这一首**。播放列表（队列）里只有它，不会顺手把前面几十首都塞进去 |
| 文件浏览行尾的 **＋** | 把这一首**追加到播放列表末尾**，不打断正在播的歌 |
| 曲库行尾的 **＋** | 同上 |
| 曲库工具栏的 **「全部入队」** | 把当前列表（已加载的部分）整体加入播放列表 |
| 专辑视图里专辑头部的 **播放** | 整张专辑入队，从第一首开始 |
| 播放条上的 **Q** | 打开播放列表，可以点选、清空 |

> 早期版本点一首歌会把"当前列表"整批入队，于是用户看到"播放列表里出现这首歌
> 之前的所有曲目"。现在**点哪首放哪首**，要批量请用「全部入队」。

### 4.4 数据源

磁贴墙。每块磁贴显示：类型图标与名称、类型名、是否只读/已停用、根路径、在线状态（带延迟毫秒数）、
已索引曲目数、上次扫描时间。鼠标移上去右上角浮出 5 个图标按钮：**测试连接 / 扫描建索引 / 浏览目录 / 编辑 / 删除数据源**。
类型是实验性协议时，名称后面会有 **「实验性」** 徽标。详见 [第 5 章](#5-数据源)。

### 4.5 曲库浏览

按"歌"看的表格。工具栏从左到右：数据源下拉、搜索框（支持错别字与拼音缩写，旁边的 **「模糊」** 开关可关掉）、
排序下拉（按路径/文件名/标题/作者/专辑/时长/码率/体积/音质分/修改时间）、**「↑ 升序 / ↓ 降序」**、
**「无损」**、**码率下限**（≥128k … ≥900k）、**「有封面」**、**「重置」**、
**「曲目 / 专辑」**两种显示方式、**「加载更多」**、**「显示列」**、**「导出 CSV」**。
点一行打开**曲目详情**（完整路径、格式、码率、采样率、声道、位深、音质分、抽样哈希等），
详情里可以 **「复制路径」/「重新解析标签」/「编辑标签」/「在文件浏览中打开」**。
专辑视图里每张专辑可以 **「播放」**（整张进队列）或只加入队列。

### 4.6 文件浏览

按"真实目录"看。左边目录树（每个文件夹标着曲目数，可按文件数/名称/时间排序，可勾选多个目录批量操作），
右边是文件列表与选中操作条。工具栏里比较重要的几个：
**「新建目录」**、**「当前目录操作」**、**「智能整理」**、**「查找并分析去向」**、**「上传入库」**、**「查重」**。
详见 [第 7 章](#7-文件浏览)。

### 4.7 中转站

两栏：上面是 **中转站**（我还没决定放哪的文件），下面是 **上传暂存区**（上传了但还没走完入库流程的批次）。
按钮有 **「智能分配去向」「归入目录…」「还原原位置」「移入回收站」**，暂存区那边有
**「转入中转站」「清空壳」「清滞留」「删除批次」「继续入库」**。详见 [第 13 章](#13-中转站)。

### 4.8 双栏对比

左右两个下拉选库 → **「⇄ 开始对比」** → 上方统计卡（已配对 / 仅左侧 / 仅右侧 / 内容完全一致 / 需人工确认 / 两侧总量），
下方两栏逐行对照（滚动是同步的）。过滤条：**全部 / 已配对 / 仅左侧 ◀ / 仅右侧 ▶ / 名字不一致**，右边还有一个过滤输入框。
点任意配对行看**配对详情**（两边参数 + 判定依据 + 各自的试听按钮）。
右上 **「生成同步计划」** 进入计划对话框。详见 [第 10 章](#10-双栏对比与同步)。

### 4.9 查重

工具栏：范围下拉（全部数据源或某一个）、**各库内部查重 / 跨库查重（两个库之间）**、
哈希强度 **抽样哈希（快，推荐）/ 全量哈希（慢，最准）/ 不算哈希（只看文件名+时长）**、
严格度 **很严 / 标准 / 宽松**、**「开始查重」**，最右是 **「区分不同版本」** 开关。
出结果后出现第二条工具栏：保留策略、**「应用到全部组」**、**「重新勾选全部」**、显示筛选
（**全部组 / 内容完全一致 / 仅相似 / 已忽略**）、**「全部勾选」「忽略全部」「只看已忽略」**、**「生成清理计划」**。
详见 [第 11 章](#11-查重)。

### 4.10 操作记录

上半是**任务表**（类型、状态、进度、信息、耗时、开始时间，以及暂停/继续/取消/接着做完按钮），
下半是本次会话的**操作历史**（每次执行的成功/冲突/跳过/阻断/失败计数，可展开看逐文件结果）。
顶部有 **「打开任务中心」「刷新」「清空操作记录」**。详见 [第 14 章](#14-操作记录与恢复)。

### 4.11 设置

分四块：**算法与性能**、**中转站与上传暂存区**、**界面偏好记忆**、**运行环境 + 后台日志 + 索引统计**。
右上角是 **「保存设置」** 和 **「从文件重载配置」**。详见 [第 15 章](#15-设置项参考)。

## 5. 数据源

"数据源" = 一个音乐库的根位置。所有扫描、对比、查重、搬运都以数据源为边界：
**移动只能在同一数据源内做**，跨数据源要显式用"跨库传输"。

### 5.1 支持的类型

| 类型（界面显示名） | 是否实验性 | 能否写入 | 必填项 |
| --- | --- | --- | --- |
| **本地 / 已挂载盘符** | 否 | 可以 | 本地根路径 |
| **SFTP（SSH 文件传输）** | **是（实验性）** | 可以 | 主机 / 地址、远端根路径（端口默认 22；用户名/密码视服务器而定） |
| **WebDAV** | **是（实验性）** | 可以 | 主机 / 地址、远端根路径（基地址可选，用户名/密码按需） |
| **HTTP 目录（只读）** | **是（实验性）** | **不可以**（只能读） | 主机 / 地址、远端根路径（基地址可选） |
| **SMB / Windows 共享** | **是（实验性）** | 可以 | 主机 / 地址、共享名、远端根路径（端口默认 445；用户名、密码、域按需） |
| **FTP / FTPS** | **是（实验性）** | 可以 | 主机 / 地址、远端根路径（端口默认 21；用户名/密码按需） |

对话框里带 `*` 的是必填；密码留空等于"匿名 / 免密"。

**为什么除了"本地"以外全标"实验性"？**

因为这些协议**只做完了代码实现，从来没有对着真实服务器完整跑过一遍**。界面在选中这类类型时会把这句话直接摊开给你看，
并按类型分别说明"没验证到什么程度"，例如：

- SFTP：*只做过代码实现，没有连过任何真实 SSH 服务器。上传、断点读、删除进回收站（改名）这几条路径都未验证。*
- WebDAV：*只做过代码实现，没有连过任何真实 WebDAV 服务端。PUT / MKCOL / PROPFIND / MOVE 的组合行为未验证。*
- SMB：*只做过代码实现，没有连过任何真实 Windows 共享。*
- FTP：*只做过代码实现，没有连过任何真实 FTP 服务器。MLSD 列目录、REST 断点读、回收站改名都未验证。*
- HTTP 目录：*只做过代码实现，没有连过任何真实 HTTP 目录服务。各服务端 autoindex 的 HTML 格式差异较大，解析可能失效。*

所以用它们的时候，界面上会给出两条具体建议：**① 先勾上「只读」当保险丝**，确认能正常浏览、播放之后再取消；
**② 先用一个小目录试一次搬运**，核对结果再上大批量。

### 5.2 每种类型要填什么

添加/编辑对话框的字段是**按类型显示**的：

- **本地**：本地根路径（可用 **「选磁盘」** 从盘符列表里挑，还能看到每个盘的剩余空间和"可移除"标记）。
- **网络类型（SFTP / SMB / FTP / WebDAV / HTTP）**：主机 / 地址、端口、用户名、密码、远端根路径；
  SMB 另填 **共享名 + 域（可选）**；WebDAV / HTTP 另填 **基地址（可选）**。
- 密码框的提示语很关键：第一次填就写上；**编辑时留空表示"不改密码"**，不会把已保存的密码清空。
  密码不是明文存在配置文件里，而是单独放在数据目录下的 `secrets.toml`。

远端根路径的写法：FTP/SFTP/WebDAV 用 `/` 开头（如 `/music`），SMB 用 `\\主机\共享` 形式。
它是"这个库的根目录"，之后所有路径都相对它算。

### 5.3 「只读」开关是干什么的

勾上之后，这个数据源**任何写入、删除、改标签都会被拒绝**，界面上相关按钮会失效，后端也会直接拒绝（返回"被拒绝"而不是假装成功）。
浏览、搜索、试听、对比、查重这些只读操作完全不受影响。

建议的用法：**把作为"源"的那一侧勾成只读**，这样无论后面怎么误操作，都不会反向覆盖好文件。
取消勾选随时可以恢复可写——文件浏览页工具栏右侧还有一个 **「设为只读 / 取消只读」** 的快捷按钮，不用翻回数据源页。

### 5.4 慢速盘模式

对话框里有一个 **「慢速盘模式（U 盘 / 移动硬盘 / 网络位置建议开启）」**。开启后：扫描并发压到 2、哈希并发压到 1，
并且**跳过按内容的全量哈希**（U 盘上做全量哈希会让扫描从几分钟变成几十分钟，中途拔盘还会白干）。
内置硬盘不要开，只会白白变慢。

新建数据源时，如果你在本地路径框里输入了一个可移除设备或网络位置的路径（或者从「选磁盘」里选了它），
工具会**自动帮你勾上「只读」和「慢速盘模式」**，并在右下角提示"识别到可移除设备，已默认勾选…（可取消）"。
这是保守的默认值，你可以随时取消。

### 5.5 「跟随符号链接」

只有本地类型有这个选项。默认关闭，避免符号链接成环或者意外顺着一根链接把整个磁盘扫进来。

### 5.6 删除数据源

磁贴右上角 **🗑（删除数据源）**。确认框说得很清楚：**只删除配置，不会动服务器/磁盘上的文件**。
之后还会再问一句"是否同时清空它的索引记录？"——选"清空索引"就把这个库在索引里的曲目记录也删掉（同样不影响文件）；
选另一项则保留索引记录。

### 5.7 便携设备（手机、相机、MTP 播放器）：只探测，不支持

添加数据源时点 **「选磁盘」**，工具会去问系统"现在插着什么盘"。对于插着的手机/相机这类**便携设备（MTP）**，
它会**列出来，但明确标记为"暂不支持"，不允许添加成数据源**。

原因是技术性的，但结论对你有用：MTP 不是可挂载的文件系统，访问它必须走 Windows 的便携设备 COM 接口或第三方原生库（libmtp），
而这个项目刻意**只依赖标准库 + 少数纯 Python 包**，所以做不到。与其让你建一个永远连不上的数据源，不如如实告诉你。

界面会给出两条真正可行的替代路径：

1. 在手机/相机上把 USB 模式切成「文件传输 / U 盘模式」，它就会变成一个盘符，用 **「本地」** 源直接加；
2. 或者用厂商的同步工具先把歌拷到本地目录，再加那个目录。

## 6. 扫描与索引

### 6.1 扫描到底做了什么

一次扫描会：

1. 从数据源根目录（或你指定的子目录）**遍历全部子目录**，只收集音频扩展名的文件；
   遍历时会跳过 `.music-sync-trash`、`.msh`、`$RECYCLE.BIN`、`System Volume Information` 这几个目录。
2. 对每个文件**解析标签**（标题、作者、专辑、音轨号、碟号、年份、流派、封面、时长、码率、采样率、声道、位深）。
   大文件只读文件头部，不会为了读个标签把几十 MB 整份拉下来（远端源上这一点最要紧）。
3. 顺便登记**同目录的封面图**（`cover.jpg` / `folder.png` 之类），供列表显示。
4. 算一个**音质分**，以及一个"歌键"（标题 + 主艺术家 + 时长桶），用于后面的配对与查重。
5. 可选地算**抽样哈希**（扫描对话框里勾"扫描时顺带计算抽样哈希"）——这一步更慢，但之后查重更准。
6. 把结果写进索引；扫描结束时会**清理索引里已经不存在的记录**。

### 6.2 扫描是增量的

判断依据是**文件大小 + 修改时间**（远端源还会参考 etag）。两者都没变就直接复用索引里的解析结果，
不再重复读文件。所以第一次扫描最慢，之后的扫描通常快得多，界面上会报"缓存命中 N"。

### 6.3 扫描对话框里的三个选项

- **只扫描子目录（留空 = 整库）**：填 `Rock/2024` 就只扫这个子树。几万首的大库建议先拿一个子目录试水。
- **并发线程数**：对本地机械盘可以从 4 起试；SSD 上 8～16 都行。这是本次扫描的临时值，
  全局默认在 **设置 → 扫描并发线程**。
- **扫描时顺带计算抽样哈希（更慢，但查重更准）**：不勾也能查重，只是查重时才会现算哈希。

### 6.4 什么时候需要重扫

- 你在**工具外面**（资源管理器、别的软件、另一台机器）挪动/改名/新增/删除了文件——索引不知道，必须重扫。
- 你刚把文件**复制**进某个库（复制过来的目标文件在下次扫描前只有文件名和大小，没有标签详情）。

反过来，**工具自己做的操作会自动同步索引**：移动、改名、删除到回收站、跨库搬运成功后，索引里的路径会立即更新
（删除的会立即从索引移除）。所以这些操作做完不用手动重扫。

### 6.5 索引存在哪

| 东西 | 位置 |
| --- | --- |
| 配置 | `%USERPROFILE%\.music-sync-hub\config.toml` |
| 口令 | `%USERPROFILE%\.music-sync-hub\secrets.toml` |
| 索引数据库 | `%USERPROFILE%\.music-sync-hub\index.sqlite3`（另有 `-wal` / `-shm` 两个伴随文件） |
| 日志 | `%USERPROFILE%\.music-sync-hub\logs\msh.log` |
| 标签备份 | 应用数据目录下（详见「编辑标签」里的 **「备份」** 按钮） |
| 上传暂存区 | 默认应用数据目录下的 `uploads/`（可在设置里改） |
| 中转站 | 默认程序目录下的 `station/`（可在设置里改） |

删掉 `index.sqlite3` **只是清索引**，重新扫描就能重建，**不会动你的音乐文件**。

## 7. 文件浏览

曲库浏览是按"歌"看，文件浏览是按"文件夹"看——整理音乐时人是按文件夹思考的：哪个文件夹塞了几百首、哪首放错了地方。

### 7.1 目录树与列表

- 左侧目录树：每个文件夹后面标着**它包含的曲目数**（含子目录）。树上方可以切换**文件夹排序：按文件数 / 按名称 / 按时间**。
  没扫描过的目录会标「未建索引」（数字只数了一层）。
- 右侧列表：文件夹行（名称、曲目数、本层数量、体积、修改时间）+ 音频文件行（封面、文件名、标题·作者、大小、时长、修改时间、音质分、▶ 试听）。
- 面包屑导航在工具栏下方，点任意一级可以跳回去。工具栏上的 **「上级」** 与 **「刷新」** 也一样。
- 工具栏右侧有一条**磁盘余量条**：显示当前目录所在盘的剩余空间（紧张时会变色，<5% 或 <5 GB 标红），
  旁边就是 **「设为只读 / 取消只读」** 快捷开关。

### 7.2 勾选、全选、部分选

列表左侧每行一个勾选框。选中条上的全选是**三态**的，和资源管理器一致：

- 一个都没选 → 显示 **「全选本目录（N）」**；
- 选了一部分 → 勾选框显示**半选**，文案变成 **「已选 12 / 271」**；
- 全选 → 勾选框打勾，文案 **「取消全选（N）」**。

选中条右侧还会显示"已选 N 个 · 体积"，以及"其中 X 个已在候选区"。

### 7.3 快速集合

选中几首后，可以用 **「同作者」/「同专辑」/「整个文件夹」** 把散落在库里其它目录的同作者/同专辑曲目一次性集合进来
（只合并到"已选"里，不会立刻动文件）。这样批量处理同一张专辑特别快。

### 7.4 批量移动

选中 → **「移动到…」**。对话框里：目标目录（默认当前目录）、**「浏览 / 搜索目录…」**（可以直接搜目录名跳过去，不用一层层翻）、
**「新建子目录…」**、同名冲突策略（**跳过 / 自动改名加 (2) / 覆盖目标**）、**「预演」**、**「执行移动」**。

- **移动只发生在同一个数据源内部**，本质是改名，不会复制一份再删一份。
- 移动完成后索引会立刻更新，列表跟着变。
- 同名冲突默认是"跳过"——**绝不覆盖**已有文件。
- 可恢复性：**移动本身可恢复**（再移回来就行），但**如果你选了"覆盖目标"，被覆盖的那一份是不可恢复的**。

### 7.5 编辑标签

选中 → **「编辑标签」**（曲目详情弹窗里也有）。可以改：标题、作者、专辑、专辑作者、年份、流派、音轨号、碟号、备注、封面。

- 批量编辑时，只有**左侧勾选了的字段**才会被写入——不会顺手把其它字段清空。
- 写入前会弹一个**"从什么变成什么"的预览**，确认了才写。
- 写入流程是 **备份 → 写入 → 回读校验**，写入前会自动把原始标签备份一份；
  编辑框底部的 **「备份」** 按钮可以打开备份列表逐个还原；写入完成后，结果弹窗里还有 **「撤销这次修改」**
  可以一次性把这批文件的标签还原成写入之前的样子。
- 不是所有格式都能改标签，见 [第 20 章](#20-已知限制)。

### 7.6 删除到回收站

选中 → **「移入回收站」**。确认框会写明数量和体积，并告诉你删除 = 移动到 `<该库根目录>/.music-sync-trash/日期/`。

- **可恢复**：文件还在磁盘上，只是换了位置；操作用到的具体回收站路径会显示在结果里，也会记在「操作记录」里。
- **能一键还原**：文件浏览工具条上点 **「回收站」** → 勾选 → **「还原选中」**。
  默认还原回**原来的目录**（删除时会记下来），同名默认**跳过**，也可选"自动改名"，**绝不覆盖**。
  面板里还会显示每一项的原位置 / 大小 / 删除时间。
- 确认不要了可以 **「彻底删除…」**（要输入"永久删除"四个字，不可恢复）。
- 老版本删的文件没记录原位置，也能列出并还原 —— 会落回库根目录。
- 目录树里对某个文件夹点右键 → **「删除（移入回收站）」** 会把整个目录连同里面的文件一起搬过去，同样可恢复。
  如果你在删除对话框里勾了 **「我要永久删除，不进回收站」**，会要求你**手动输入"永久删除"四个字**才执行——那一步**不可恢复**。

### 7.7 跨库传输

选中 → **「跨库传输…」**（至少要有两个数据源）。对话框里：目标数据源（只读的会置灰并说明原因）、
目标目录（可以不选，默认落到目标源根目录）、同名冲突策略、**「额外比对内容哈希（更慢；默认只比大小）」**、
**「预检」**、**「开始传输」**。

它和"移动"的区别是本质性的：**跨库传输的顺序固定是 先复制 → 校验通过 → 再删源**，删掉的源进回收站。
任何一步失败，源文件都还在。目标那侧是"先写临时文件再改名"，所以中途断了不会留一个看着完整的半截文件。

点 **「开始传输」** 后会先二次确认（确认框里会写明"先复制 → 校验 → 再删源"以及你选的同名冲突策略），确认了才动文件。

**中断了可以续传**：复制过程中写的是 `<目标>.mshpart`，旁边记着它来自哪个源文件、
源多大。下次对**同一个源文件**再传，会从已完成的字节处继续（结果里显示
"断点续传：从 N 字节处继续"）；换了源文件则从头写 —— 绝不会把两份内容拼在一起。
临时文件超过 24 小时没人管时，启动时会自动清掉。
数量上限：一次最多 2000 个文件；源和目标不能是同一个数据源（同库内请用「移动到…」）。

### 7.8 非音乐文件：能做什么，不能做什么

这一点必须先说清楚，因为界面看起来像文件管理器，但它**不管理非音乐文件**：

**能做的**

- 你在文件夹里放着的 `.jpg` / `.nfo` / `.cue` / `.txt` 等文件，会**跟着目录操作一起被处理**：
  重命名目录、移动目录、删除目录（移入回收站）都是对**整个目录**做的，里面的非音频文件也在其中。
- 在「中转站」和「上传暂存区」里，如果那里混进了非音频文件，界面会**专门列出来**告诉你"它们占着磁盘、不会归入曲库"，
  并允许你把它们移入回收站。

**不能做的**

- **不在文件列表里显示。** 文件列表只列音频扩展名的文件；一个目录里只有非音频文件时，会显示"这个文件夹里没有音频文件"。
- **不能勾选、不能移动、不能编辑标签、不能进候选区、不能跨库传输。** 这些操作的对象都是"曲目"。
- **不会自动归入曲库。** 拖拽导入、上传入库都会把非音频文件**忽略掉**（会明确告诉你忽略了几个）。
- **不计入曲库统计。** 曲目数、体积、查重、对比，全部只算音频。

### 7.9 其它实用操作

- **新建目录 / 重命名 / 移动目录 / 清理空文件夹**：右键点一个文件夹（或点行尾的 **⋯**）→ 菜单里都有。
  当前目录也可以操作：在列表空白处右键。
- **清理空文件夹**：会先扫出范围内所有"空"目录（没有音频、也没有非空子目录），**默认全选**，
  你可以取消勾选保留某些；还有 **「只保留最外层」** 的快捷按钮。删除前后端会再验一次，非空目录一律跳过并如实报告。
  这个操作**不可撤销**（但里面本来就没有文件）。
- **拖拽导入**：从资源管理器把文件拖进文件列表，松手就导入到**当前目录**（拖拽时会明确显示落点）。
  同名冲突按"跳过"处理，绝不覆盖。这条路径走的是和上传入库同一套接口，所以也会查重。
- **查找并分析去向**：输入关键词搜一首歌，工具会在**库里既有的文件夹**之间给出"它该放在哪"以及依据
  （目录名一致、目录里已有同专辑的曲目等），并允许直接搬过去。它**不新建目录、不重排整库**。

## 8. 候选区

候选区是文件浏览页底部的一块**跨目录暂存区**。

**它解决什么问题**：想在多个文件夹里各挑几首歌一起处理时，"换一个目录选择就被清空"是最烦的。
候选区让你把挑中的文件先收进来，然后继续去别的目录挑，最后一次性处理。

**怎么加**

- 文件浏览的选中条 → **「加入候选区」**（按钮上会显示还能加几个，已经在候选区里的会自动跳过）。
- 左侧目录树里勾选若干目录 → 工具条上的 **「加入候选区」**（把那些目录里的文件一次性收进来）。
- 曲目详情里也可以"加入队列"，但那是**播放队列**，和候选区不是一回事。

**里面有哪些操作**

- **「智能分配去向」**：用「智能整理」的同一套判定规则，只针对**你勾选的这些文件**算出去向。
  点开后会先让你选规则，**再预览，最后才采用**（不会点一下就自动分好）：
  1. **分组依据**：作者 + 专辑（推荐）/ 仅作者 / 仅专辑
  2. **目录结构**：分层（作者/专辑）/ 单层
  3. **最少同组**：一个目录至少几首才单独建目录（不够的落到收纳区或留在原处）

  点「预览去向」会列出"哪个目录、几个文件"，确认无误再点「采用这些去向」。
  采用只是**填好去向**（分好颜色），**还没有移动任何文件** —— 你可以逐项改，
  最后再点「执行移动」。
- **「手动设去向…」**：自己挑一个目标目录。
- **「检查失效」**：逐个确认这些文件是否还在磁盘上（放久了可能已被移走）。
- **「执行移动」**：按去向分列执行批量移动，同名冲突按"跳过"处理，**绝不覆盖**。
- **「移出候选区」**：只是从清单里拿掉，不动文件。

**和"移动"的区别**：候选区**本身不搬任何文件**，它只是一份"待办清单"。
真正动文件的是你点 **「执行移动」** 那一刻，而且执行的是普通的同源移动。

**为什么只收音频**：候选区整条链路（移动计划、跨库传输、智能整理）都是按"曲目"算的。
把 `.nfo` / `.jpg` 放进来，轻则界面上多出一堆没有封面的怪条目，重则被跨库传输捎到对面去。
所以加入非音频文件时会被**跳过并提示**（"跳过 N 个非音频文件（候选区只收音频）"）。

**颜色和"待定"**：去向相同的文件自动同色（7 种颜色循环使用），"待定"（还没设去向）用警示色，不参与执行。
候选区的内容会存在浏览器里，**刷新页面不会丢**。

## 9. 上传入库

入口：文件浏览工具栏的 **「上传入库」**。它把散装文件按现有音乐库结构归位，**分三步走**，和智能整理一个套路——先看方案再动手。

```
1 选文件  ›  2 分析去向  ›  3 确认入库
```

### 9.1 第 1 步：选文件（先进暂存区，不碰音乐库）

把文件拖进虚线框，或点 **「选择文件…」**。上传是分批进行的，会显示"已传 N / 总数""已传字节 / 总字节""速度""约剩多少秒"。

**关键点：文件先落到"上传暂存区"，不会直接进音乐库。** 因为上传的文件名/标签常常是乱的，
直接写进库里就是制造垃圾。暂存区默认在应用数据目录的 `uploads/`，有独立容量上限（设置里的 `staging_max_gb`，默认 5 GB）。
暂存区里还没处理完的批次会在这里列出来，点一下就能接着处理。

### 9.2 第 2 步：分析去向

工具会读每个文件的标签、跟库里**已有的目录**比对，然后按目标目录**分列**显示（每个去向一列，带颜色和完整路径），
每列标注判定依据：自定义映射 / 库里已有该专辑目录 / 库里已有该作者目录 / 库里找到相似目录 / 建议新建目录 / 收进收纳区。

在这一步你能做的：

- 单个文件 **「更改去向」**（挑目录）；
- 给某个专辑/作者建 **「映射」**：以后凡是这个标签的文件，自动建议进指定目录；
- **「全选」「全不选」「重新分析」**，也可以按列一键勾选整列。

### 9.3 重复检测

顶部有 **「检查是否重复」**（查过一次后变成"重新查重"）。它会逐文件比对**库内曲目内容**，把疑似重复标出来：

- **库内已有相同内容**（内容哈希一致，铁证）；
- **疑似重复**（只是文件名与体积相同）。

发现重复时会弹一条横幅，给你两个按钮：**「取消勾选这些重复项」** 或 **「仍然全部入库」**。
它只提示、不替你做决定，你的勾选始终有效。

### 9.4 第 3 步：确认入库

确认框会列出"目标 N 个目录、各多少个文件"，并**先检查目标盘剩余空间**：
装不下会直接拦住（"目标盘只剩 X，这一批需要 Y，请先清理磁盘或少选一些分批入库"）；
超过剩余空间一半会给出橙色提醒。

点 **「开始入库」** 后文件才真正搬进音乐库。规则：

- 同名冲突按 **"跳过"** 处理，**绝不覆盖**已有文件；
- 搬完会**自动后台刷新索引**，稍等一下就能在文件浏览里看到；
- 失败或被跳过的文件会**留在暂存区**（结果里会写"暂存区还剩 N 个文件"），方便你处理后再来一次。

## 10. 双栏对比与同步

### 10.1 开始对比

左右各选一个库（不能是同一个），点 **「⇄ 开始对比」**。对比是**后台任务**，会显示进度、可以取消，刷新页面也不会丢。

结果上方是统计卡：**已配对 / ◀ 仅左侧 / 仅右侧 ▶ / 内容完全一致 / 需人工确认 / 左库总量 / 右库总量**。
如果曲目数超过"单次对比上限"，会有一条橙色提示告诉你"仅对比了左 X/Y · 右 Z/W 条"，并建议缩小范围或调大上限。

下方两栏逐行对照，行左侧的色条含义：**绿 = 已配对 / 黄 = 单侧独有 / 紫 = 需确认**。

### 10.2 配对详情

点任意配对行，弹出**配对详情**：左右两份各自的封面、标题、作者、专辑、格式、码率、采样率、位深、时长、体积、音质分、路径，
下面列出**判定依据**（为什么认为它们是同一首歌）、名称相似度百分比、时长差、体积差、音质差，
置信度不高时会明确写"可能是不同版本（现场 / 混音 / 剪辑），请试听后决定"。两边都有试听按钮。

### 10.3 生成同步计划

右上 **「生成同步计划」** 打开对话框，左边是"补齐方向"，右边是"镜像/清理（危险）"。

**补齐方向（左栏）**

| 选项 | 含义 |
| --- | --- |
| **左 ➜ 右** | 把左库独有的文件复制到右库 |
| **右 ➜ 左** | 把右库独有的文件复制到左库 |
| **双向补齐** | 两边互相补 |

- **目标存在同名文件时覆盖（默认跳过）**：这个勾选框和计划表里的"目标存在时"下拉框是**同一个开关**，改一个另一个会跟着变。
- **同时统一文件名（把一侧改成另一侧的名字）**：生成"重命名"步骤，目标是让两边文件名一致。
- **用「先复制→校验→再删源」的方式搬运（跨盘/跨库更安全）**：勾上之后，"复制补齐"会变成**安全搬运**——
  补过去、**校验大小一致之后**才删源那份（进回收站）。往 U 盘或网络位置搬、或者你的真实意图是"搬"而不是"留副本"时选它。
- **只处理某个子目录（可选）**：比如 `Rock/周杰伦`，只在这个子树里比对与生成步骤。

**镜像 / 清理（右栏，危险）**

- **镜像模式：右库中左库没有的文件 → 移入回收站**。
  注意它是**单向**的：只清理**右库**里左库没有的文件。删除进 `.music-sync-trash/日期/`，不会直接销毁。
  它和"右➜左补齐 / 双向补齐"是**互斥**的组合：勾了镜像又选了这两种方向时，工具会自动跳过"右➜左"的补齐步骤，
  并用一条警告说明原因（否则同一个文件会一边被复制、一边被删除，可能两头落空）。
- **同时列出两侧内容完全一致的重复（可清理其中一份）**。
- **匹配严格度**：宽松（多配一些，可能有误配）/ 标准（推荐）/ 严格（只配非常像的）。

### 10.4 预演与执行

计划生成后会列出**逐步表格**：操作（复制 / 移入回收站 / 永久删除 / 重命名统一）、源、源路径、目标、目标路径、体积、风险
（**高危 / 注意 / 安全**）、原因。每行可单独勾选，表头勾选框可全选/全不选。

- **「预演（不写入）」/「预演这批步骤」**：只做安全检查并列出结论（将执行 / 已存在跳过 / 被阻断 / 异常），**一个字节都不写**。
- 执行前的选项：**「复制后校验大小」**（默认勾选）、**目标存在时跳过 / 覆盖 / 改名 (2)**。
- **「执行选中步骤」** → 二次确认（会单独告诉你其中有几个是删除步骤）→ 执行。

执行结果会给出 成功 / 跳过 / 阻断 / 失败 与已复制、已清理的体积，并逐条列出结果；
同时自动记进 **「操作记录」**。同一时刻只允许一个写操作在跑，别的页面会提示"已有任务在执行"。

## 11. 查重

### 11.1 单库内部 vs 跨库

- **各库内部查重**：在每个数据源内部各自找重复。
- **跨库查重（两个库之间）**：把不同数据源之间的文件两两比对。

三个库以上做跨库查重时，工具会把"两两配对"的结果**合并成互不重叠的组**。
这样"每组保留一份"才有意义——否则同一份文件会出现在多个组里，可能出现"在这一组保留、在另一组又被删"的矛盾。
合并后，3 个库里的同一份文件会变成"一组 3 条成员"，和单库查重的组形状一致。

### 11.2 相似度阈值（严格度）

- **很严（几乎同名）**；
- **标准**（默认）；
- **宽松（捕捉改名的重复）**。

调得越宽，越能抓到"被改过名的重复"，但也越可能出现"其实不是同一首"的误配。拿不准就用默认。

### 11.3 哈希强度

| 选项 | 含义 | 什么时候用 |
| --- | --- | --- |
| **抽样哈希（快，推荐）** | 取文件头尾若干 KB 算指纹；体积在组里是独一份的文件会被直接跳过（不可能是别人的副本） | 日常 |
| **全量哈希（慢，最准）** | 整份读完再算 | 要"字节级铁证"、或者抽样有疑点时 |
| **不算哈希（只看文件名+时长）** | 只按名字与时长分组 | 只想快速看个大概，**不要用它做删除决定** |

### 11.4 哪些能自动清理，哪些必须你自己判断

查重结果把每个组分成"子簇"：

- 🟥 **内容完全一致**（组内存在 ≥2 份**字节完全相同**的副本）：**可以安全清理**，界面会按你的保留策略自动勾选多余的那几份。
- 🟨 **仅相似 / 同名但内容不同**（不同音质、不同版本）：**永远不会被自动勾选**，必须你自己听完决定留哪份。
  组头上会标"同名但内容不同 · N 个版本"，组内每份还会标"内容版本 1/2"这类信息。

**清理永远只在"字节完全一致"的子簇内部删。** 合并视图下不同版本只是摆在一起方便对照，清理时绝不会碰到它们。

### 11.5 界面上的三层口径（别被"只有几组"骗了）

- **总组数**：后端返回的全部重复组；
- **内容完全一致**：组内存在字节相同子簇的组数（可安全清理）；
- **仅相似**：只能人工判断的组数。

筛选（全部组 / 内容完全一致 / 仅相似 / 已忽略）只影响**显示**，永远不改变总数；
界面顶部会明确写出"共 N 组：内容完全一致 X 组、仅相似 Y 组。当前显示全部 N 组"。

### 11.6 怎么选保留哪份

- 组内每行前面有一个单选钮，选中那行会标 **「保留这份」**，其余标 **「将移入回收站」**。
- **保留策略**：音质最好的（默认）/ 体积最大的 / 最早的 / 最新的，选完点 **「应用到全部组」**。
- 单个组想自己挑：**「按音质推荐保留」** 或直接点单选钮。
- 组头上可以 **「取消勾选」**——这一组就完全不参与清理（结果仍然显示，之后可以 **「重新勾选」**）。
- 还可以 **「忽略全部」**（这一步不清理任何文件）、**「只看已忽略」**（逐个确认这些真不用管）、**「全部勾选」**。

### 11.7 执行清理

点 **「生成清理计划」** → 弹窗会写清楚"将把 N 个重复文件（约 X）移入回收站，涉及 K/M 组"，
并显示预演结果（将删除 / 被阻断）→ 点 **「确认移入回收站」** → 还要在**高风险确认框里手动输入"确认清理"**四个字。

- **可恢复性**：文件进的是 `.music-sync-trash/日期/`，磁盘上还在；但**库内索引会同步删除**，
  所以"恢复"意味着你要用资源管理器把文件搬回原处再重扫。
- 「仅相似」的组**完全不会被触碰**。
- 执行完会自动重新查一次，你可以立刻看到剩下什么。

## 12. 智能整理

目标：把**放错位置**的歌挪到该在的地方。入口是文件浏览工具栏的 **「智能整理」**
（右键某个文件夹也有 **「智能整理这个文件夹…」**，只处理那个目录）。

核心原则写在界面上：**只在"可证明位置有误、且存在明确目标目录"时才移动文件**；它不新建没有依据的目录层级，也不重排已整理好的结构。

### 12.1 三个核心选择

1. **① 按什么分组**：**仅作者** / **作者 + 专辑**（默认）/ **仅专辑**。
2. **② 目录结构**（只在"作者 + 专辑"时可选）：**两层：作者 / 专辑**（默认）/ **单层：仅作者**。
3. **③ 达到几首才单独建目录**：默认 **5**。一组曲目数达到这个数才为它新建目录；不到门槛且库里没有对应目录的组**保留原位**。

这三项（加上忽略范围、收纳区、映射规则）会**按数据源记住**，下次打开智能整理自动恢复，并在右下角提示"已恢复上次的设置"。

### 12.2 门槛与"保留原位"

门槛的意思是"值不值得为它开一个目录"。比如库里只有 2 首歌属于某张冷门专辑，为它单独建一个文件夹反而更乱，
所以默认策略是 **保留原位（推荐）**——不动它。

如果确实要把这些"不够门槛"的组收起来，可以在高级设置里把 **收纳区** 的策略切到 **「归入收纳区」**，
并勾选一个已有的收纳目录（比如"单曲01""英语歌精选集""日语歌精选集"这类）。
工具会从库里自动认出这类"收纳型"目录并标上 **「已识别」**，你也可以手动勾选其它目录。

收纳目录在整理里有两个作用：它**不会被当作整理目标**（不会把别的歌塞进去），
并且是"不够门槛的组"在选了「归入收纳区」之后的去处。所以它更适合当"杂物箱"，不适合当"专辑目录"。

### 12.3 忽略范围

高级设置里有 **忽略范围：勾选的目录不参与整理**。列表按曲目数排序，勾上就忽略（含它的全部子目录）。
两个快捷按钮：**「全部整理」**（清空忽略）和 **「只整理根目录」**（把最外层目录都忽略）。

从左侧目录树勾选若干目录后点 **「整理这些」**，会把这个选择直接带进忽略范围里，省得你在高级设置里一个个找。

### 12.4 判定顺序（目标目录怎么定的）

界面上有一个可展开的"判定顺序"，逐条如下：

1. **自定义映射**（优先级最高）；
2. 库内已有**同名专辑**目录 → 直接归入；
3. 库内已有**同名作者**目录 → 两层结构且该组达门槛时，在作者目录下建专辑子目录；否则保留在作者目录；
4. 库内名称**高度相似**的既有目录 → 建议并入（这项判定很保守：名字太短不比、带有互相冲突的区分词也不认）；
5. 该组曲目数达到门槛 → 新建目录；
6. 以上都不满足 → 归入收纳区（若选了）或**保留原位**；
7. 已加入"忽略范围"的目录及其全部子目录均不参与。

### 12.5 看方案、改方案

方案表每行是"一组"：分组名（专辑或作者）、目标目录、**判定依据**徽标、曲目数，以及两个按钮：
**「改目录」**（为这一组指定别的目录）、**「映射」**（为该专辑/作者建一条长期规则，之后自动归入指定目录）。

- 点行首的 **▸** 可以**就地展开这一组的曲目明细**：文件名、作者、专辑、当前目录、体积、处理状态。
  每首前面有勾选框——**取消某首就只跳过这一首**，同组其它照常（"组内全选 / 组内全不选"是快捷按钮）。
- 顶部统计：曲目总数、分组数、需移动、保留原位、新建目录、（若有）**无元数据·手工**。
- 上方还有一个"目标目录汇总"，让你先看清"整理后会变成什么结构"。

**映射规则管理**：高级设置里的 **「查看 / 编辑规则」** 会列出全部规则（命中：专辑名/作者名 → 归入目录），
可以新增、改目录、改命中、逐条删除、一键清空。规则会保存下来，下次仍然生效。

### 12.6 为什么"没有元数据的曲目"要你手工处理

方案里如果出现 **「N 首没有元数据，不参与智能整理」** 的警告块，说明这些文件**没有 artist / album 标签**。

工具不去猜。因为猜错的代价是**把它们丢进错误的目录**——一首没有标签的歌被归到某张专辑的文件夹里，
以后你自己都会以为它属于那张专辑。所以这类文件**保持原位**，需要你手工处理：

> 处理办法：在「文件浏览」里选中它们 → **「编辑标签」** 补上作者/专辑 → 再跑一次智能整理就会自动归位。

同样的道理：**"收进收纳区"是给"有元数据但不够门槛"的组准备的**，不是给"没元数据"的组准备的。

### 12.7 预演与执行

- **「预演」**：只算不动，报"将移动 N 首，跳过 X，错误 Y"。
- **「执行整理」**：确认框写明"把 N 个文件按 K 组归类；同名冲突按跳过处理（绝不覆盖）；只移动、不删除；新建的目录会按需创建"。
- 执行结果是"已移动 / 跳过 / 失败 / 搬动体积"，失败通常是因为目标已有同名文件（策略=跳过）。

## 13. 中转站

「中转站」页面上有两块，含义完全不同，别混：

### 13.1 中转站（我还没决定放哪）

- **用途**：长期存放"待定"的文件。它有**自己的目录和容量上限**（`station_dir` / `station_max_gb`，默认 20 GB），
  卡片里用容量条显示 已用 / 上限 / 百分比，**≥85% 会变色警告**，满了会**拒绝继续放入**（而不是等到磁盘写不进才报错）。
- **文件从哪来**：主要是从「上传暂存区」点 **「转入中转站」** 转过来的批次。
- **能做什么**（勾选文件后）：**「智能分配去向」**（用智能整理的同一套规则算去向）、**「归入目录…」**（自己挑目录）、
  **「还原原位置」**（放回它们原来的位置——移进来时记下了来源）、**「移入回收站」**。
  每行还有一个 **「归入」** 按钮，只处理这一个文件。
- **非音频文件**会单独列一块："非音频文件 N 个，不会归入曲库"，并允许你逐个**「删除」**（实际是移入回收站）。

### 13.2 上传暂存区（这次上传还没走完流程）

- **用途**：上传的**中间态**。属于"过路区"，归位后就该消失。默认在应用数据目录下的 `uploads/`，
  上限 `staging_max_gb`（默认 5 GB，故意比中转站小）。
- 每个批次显示：批次号、状态（正常 / **滞留** / 清单缺失 / 非音频数量）、文件数、大小、最后活动时间。
- **能做什么**：**「继续入库」**（回到上传向导接着走）、**「转入中转站」**、**「删除批次」**、
  **「清空壳」**（清掉空批次目录和散落在暂存区根目录的孤儿文件）、**「清滞留」**（清掉超过 `staging_stale_hours` 未处理的批次）。
  后三个都只动暂存区，**不会动音乐库**。
- 超过滞留时限的批次会被标成 **「滞留」** 并计入统计，提醒你该处理了（`staging_stale_hours` 设 0 则不提醒）。

### 13.3 中转站和回收站的区别

| | 中转站 | 回收站 |
| --- | --- | --- |
| 本质 | 一个**正常目录**，放"待定"的文件 | `<库根>/.music-sync-trash/日期/`，删除的落点 |
| 文件还算"在库里"吗 | 不算曲库（需要归入目录才回去） | 不算曲库 |
| 有容量上限吗 | 有（可设，满则拒绝放入） | 没有 |
| 界面能把它拿出来吗 | **能**：归入目录 / 还原原位置 | **不能**：只能用资源管理器手动搬回，再重扫 |
| 会被自动清理吗 | 不会（"清滞留/清空壳"只对上传暂存区，且要你点） | 不会（工具不会自动清回收站） |
| 用途 | 我还没想好放哪 | 我决定不要了（但先留着后悔药） |

## 14. 操作记录与恢复

### 14.1 两张表

「操作记录」页把两件事放在一起，因为它们回答同一个问题："我做过什么、现在在做什么"。

- **任务表**（最多显示最近 15 个）：类型、状态（已完成 / 进行中 / 已暂停 / 已取消 / 失败 / **心跳停止**）、进度（done/total 与百分比）、
  信息、耗时与预计剩余、开始时间。行尾按钮：**暂停 / 继续 / 取消 / 接着做完 / 忽略**。
- **操作历史**：每次执行（同步、查重清理、整理、上传入库、跨库传输、重试…）一条，带
  成功 / 冲突 / 跳过 / 阻断 / 失败 计数、搬运体积、清理体积；点 **「查看明细」** 展开逐文件结果
  （操作、对象路径、结果、耗时；删除的还会给出回收站路径）。

**失败原因会被分类**，而不是只报一句"失败"：文件不存在 / 文件被占用或权限不足 / 磁盘空间不足 / 目标已存在 /
目标只读 / 操作超时（已跳过）/ 其他。分类后面还有一个 **「重试这 N 个」** 按钮——它只挑**重试有意义**的那些
（被占用、空间不足、超时、其它）；"文件不存在""目标已存在"这类不在其中，因为它们重试也是白搭。

### 14.2 清掉不想要的任务记录

崩溃或强杀之后，上次没做完的任务会被恢复成 **"失败 + 已中断（可以尝试接着做完）"**。
如果你不想接着做（或者早就在别处处理过了），可以清掉它：

- **单条**：行尾的 **「忽略」** 按钮（垃圾桶图标）→ 从记录里删掉，重启也不会再出现。
- **批量**：顶部 **「清理已结束任务」** → 一次清掉所有 完成 / 失败 / 取消 的记录
  （正在运行的任务不会被动）。

> 「忽略」只删**记录**，不动任何文件、也不会释放正在运行的独占位。
> 运行中的任务不允许忽略 —— 那种情况请用「取消」。

另外，后台的**索引自动刷新**如果扫到了变化，也会以一条 `scan` 任务出现在这里。
那是正常的后台巡检，不用理会。

### 14.3 一次只允许一个写操作

同一时刻**只允许一个会改文件的流程**在跑。同时跑两个会基于过期的文件状态操作，这是必须禁止的。
所以你会看到"已有任务在执行：xxx。请等它结束，或在任务中心取消它"——这是保护，不是故障。
它**不排队**，因为排队的第二个任务仍然会按它拿到时的旧状态去改文件。

预演（不写入）不受这个限制，随便看。

### 14.4 崩了怎么办：接着做完

程序被强制结束、崩溃、断电之后，索引库里会留着没做完的任务记录。下次启动时，界面会**主动弹一个框**：
"上次有任务没做完 —— 检测到 N 个上次没完成的任务，其中 M 个可以接着做完"，
并列出每个任务（类型、状态、进度、是否可恢复），你可以点 **「接着做完」** 或 **「稍后再说」**。

之后也可以在「操作记录」的任务表里点行尾的 **↺（接着做完）**。

**为什么这是安全的**：恢复用的是 **"跳过同名"策略重放**剩下的步骤——
已经处理过的文件会因为"源不存在"被跳过，目标已存在的也会被跳过。所以**不会覆盖、不会重复**，最坏情况只是白跑一趟。

任务行上如果标了 **「心跳停止」**，说明那个任务的后台线程已经不在了（可能被强杀）。确认它确实没在跑之后，
可以取消它来释放独占位——否则之后所有写操作都会一直被"已有任务在执行"挡住。

## 16. 传输模式：标准 vs 快速

每个**本地数据源**可以在添加/编辑对话框里选一种传输模式，它决定"跨库搬运时删源之前要不要先量一下大小"。
配置文件里对应数据源上的 `extras.transfer_mode`（`fast` / 不写 = standard）。
搬运时按**源那侧**数据源的设置走；只有本地类型的数据源有这个选项。

| | 标准传输（推荐） | 快速传输 |
| --- | --- | --- |
| 流程 | 复制到目标 → **校验大小一致** → 才删源 | 复制完直接删源（省掉那一次大小核对） |
| 速度 | 慢一点（多一次 stat 往返） | 往网络盘 / U 盘搬大批文件时能省下可观的往返开销 |
| 能发现"目标写歪了"吗 | **能**，会当场中止并报错 | 不能；目标那份可能不完整 |
| 源会怎样 | 进回收站 | **同样进回收站**（不是永久删除） |

**什么时候选哪个**

- 本地盘之间搬、或者你要"搬得踏实"→ **标准**。
- 目标是很慢的 U 盘 / 网络位置、要搬成千上万个文件、而且这些文件在源那边还有别的备份 → **快速**。

**为什么两种模式都安全**

因为**两种模式下源文件都是进回收站，而不是被真删**。所以"快速"最坏的结果只是"目标那一份可能不完整，而源还在回收站里"，
随时能拿回来。这正是"快速模式可以存在"的前提——如果它会真删源，这个选项就不该提供。

另外，无论哪种模式，目标那侧都是**先写临时文件（`.mshpart`）再原子改名**，所以中断不会在目标留下一个"看着完整的半截文件"。

## 17. 文件安全：你能指望什么

逐条列出你可以依赖的行为（都能在界面上或执行结果里看到证据）：

1. **不点执行就不会动文件。** 所有写操作都有"预演/预检"，预演严格只读，不写一个字节。
2. **删除一律先进回收站**：`<该库根目录>/.music-sync-trash/日期/`，界面上会给出具体路径；只有你显式勾了"永久删除"（还要手打确认字）才真删。
3. **绝不覆盖已有文件**（默认策略）：目标同名时**跳过**。想覆盖必须你主动把策略改成"覆盖目标"，那一步之后**不可恢复**。
4. **搬运的顺序是固定的：先复制 → 校验通过 → 再删源。** 任何一步失败，**源文件都不会消失**。
5. **写入是原子的**：先写 `xxx.mshpart` 临时文件，成功后才改名，断网/断电不会留下"半截但看着完整"的文件。
6. **只读是硬熔断**：勾了只读的数据源，任何写入/删除/改标签都会被拒绝，并在结果里如实标成 **「阻断」**，不会假装成功。
7. **不允许越界**：路径算出来跑到数据源根目录之外时，直接报"路径超出数据源根目录，已拒绝移动"，宁可不做也不碰根外的文件。
8. **一次只允许一个写流程**：同时跑两个写操作会基于过期的文件状态改文件，所以第二个会被挡下（不排队）。
9. **单个文件失败不拖垮整批**：逐条记录原因，其它步骤继续；失败类别会分好类，并标出哪些值得重试。
10. **超时不会让界面卡死**：单个文件操作卡住（坏盘、网络盘掉线、被独占锁住）会被判超时、跳过、继续处理其它文件，最后汇报跳过了哪些。
11. **改标签有备份**：写入前自动备份原始标签，可以逐个还原；写入流程本身是"备份 → 写入 → 回读校验"。
12. **没做完的任务能接着做完**：用"跳过同名"策略重放，不会覆盖、不会重复。
13. **操作留痕**：每次执行都有逐文件结果，删除的还带回收站路径，事后能查。
14. **索引可以随时重建**：删掉 `index.sqlite3` 只清索引，重新扫描即可，**不动任何音乐文件**。

**这些是真正不可恢复的操作**，做之前请确认：

- 删除时勾了 **「我要永久删除，不进回收站」**（还要手打"永久删除"）；
- 同名冲突策略选了 **「覆盖目标」**（被覆盖的那份没了）；
- **清理空文件夹**（目录本身被删掉，虽然里面本来没有文件）；
- 执行后你自己又清空了系统回收站 / `.music-sync-trash` 目录。

## 18. 常见问题 FAQ

**Q1：为什么有些歌在智能整理里被跳过了，说"没有元数据"？**
因为那些文件没有 artist / album 标签，工具无法判断它该归到哪个作者或专辑，硬归类只会把它丢进错误的目录。
去「文件浏览」里选中它们 → **「编辑标签」** 补上作者/专辑，再跑一次智能整理就会自动归位。

**Q2：为什么扫描很慢？**
第一次扫描要读每个文件的标签与封面，几万首必然慢。可以从这几方面改善：
① 用扫描对话框的"只扫描子目录"先拿一个子树试水；
② 把 **设置 → 扫描并发线程** 调到合适值（本地机械盘从 4 起试，SSD 8～16）；
③ 如果是 U 盘/移动硬盘/网络位置，勾上**慢速盘模式**（并发会被压到 2，并跳过全量哈希）；
④ 之后的扫描都是增量的（大小/修改时间没变就用缓存），会快得多。

**Q3：为什么我的只读数据源不能写？跨库传输的目标下拉里它是灰的？**
这就是「只读」的作用：它拒绝一切写入/删除/改标签，包括作为传输目标。
要用它接收文件，得先在数据源编辑框里取消"只读"（或文件浏览页工具栏的「取消只读」）。

**Q4：传输失败了会不会丢文件？**
不会。跨库传输的顺序是"先复制 → 校验通过 → 再删源"，任何一步失败**源文件都还在**，
并且失败清单上方会明确写"下面这些源文件都还在，没有被删掉。处理完可以再传一次"。
即使走的是快速传输模式，删掉的源也是进回收站，不是永久删除。

**Q5：多库查重出来的"组"该怎么理解？为什么只有几组？**
一个"组"= 判定为同一首歌的一堆文件（可能来自不同库）。组内又会按内容指纹切成"子簇"：
字节完全相同的算一个子簇（**可安全清理**），不同音质/版本属于不同子簇（**只能人工判断**）。
"只有几组"通常是三个原因：① 筛选条只显示了"内容完全一致"或"仅相似"；② 大部分文件被"区分不同版本"拆成了不同的组；
③ 曲目数超过"单次对比上限"被截断了（界面会有橙色提示）。筛选只影响显示，不影响总数，顶部会写出真实口径。

**Q6：删掉的文件去哪了？怎么找回来？**
在 `<该库根目录>/.music-sync-trash/日期/` 下。"操作记录"里每条删除结果都会给出回收站路径。
**能一键还原**：文件浏览工具条 → **「回收站」** → 勾选条目 → **「还原选中」**。
默认还原回原目录，同名时跳过或自动改名（绝不覆盖），还原后索引会自动刷新。

**Q7：为什么文件浏览里看不到我的 .cue / .jpg / .nfo / 歌词？**
因为工具只把音频当曲目管理，非音频文件不进列表、不能勾选、不能移动。
它们只会跟着**目录级操作**被动处理（重命名目录、移动目录、删除目录），
以及在「中转站 / 上传暂存区」里被单独列出来提醒"占着磁盘、不会归库"。详见 [7.8](#78-非音乐文件能做什么不能做什么)。

**Q8：两边标签完全不一样，能配上吗？为什么有两首没配上？**
能配上：匹配主证据是**归一化文件名 + 时长 + 内容哈希**，标签只是加分项。
没配上的常见原因是防误判规则生效了：**时长差太大**（超过 2× 容差，判为不同版本：现场版/剪辑版/伴奏）、
**艺术家明显冲突**（一票否决）、或者**置信度不高**——这类会被标成"需人工确认"（紫色），
点开配对详情能看到完整判定依据，两边都可以试听。

**Q9：为什么点播放没声音？**
试听是**浏览器直接播放原始文件**（服务端只做分段转发，不转码）。能不能出声取决于你的浏览器支不支持这个格式。
常见的 `.mp3 / .m4a / .flac / .wav / .ogg / .opus` 一般没问题；`.ape / .wv / .wma / .dsf` 这类多半放不了。
另外请确认文件确实还在（如果它刚被移走或删除，会提示"源文件不存在"）。

**Q10：为什么提示"已有任务在执行"？我没在跑别的啊。**
因为**同一时刻只允许一个写操作**。可能是：另一个标签页/另一台设备在操作；或者上次被强杀后留下了"心跳停止"的僵尸任务占着位置。
去「操作记录 → 任务」看看，确认那个任务没在跑就点 **取消** 释放它。

**Q11：为什么扫描完成后的曲目数比文件夹里的文件数少？**
三种常见原因：① 里面确实有非音频文件（它们不计入曲目）；② 有些文件解析失败（结果里的"失败 N"，详情里能看到原因）；
③ 只扫了一个子目录。曲目数只算"能识别为音频、并且成功入库"的文件。

**Q12：为什么有些歌没有封面？**
封面要么来自文件内嵌的图片，要么来自**同目录的封面图**（`cover.jpg` / `folder.png` 等）。
两者都没有就是没有。另外请确认 `Pillow` 可用（设置 → 运行环境），否则封面不会被缩放显示。

**Q13：为什么点"编辑标签"提示不支持？**
标签写入只支持这些格式：`.flac`、`.mp3`、`.wav`、`.aiff`、`.m4a/.mp4/.m4b/.aac`、`.ogg/.oga`、`.opus`、`.wv`、`.tta`。
其它格式（如 `.wma`、`.mka`、`.caf`、`.ape`、`.dsf`）会报"这种格式暂不支持改标签"。它们在曲库里照样能看、能播、能整理。

**Q14：为什么对比结果说"曲目过多已截断"？**
单次对比/查重每侧最多取"单次对比上限"条（默认 8000）。超了就只比前面一部分，界面会明确写出"仅对比了左 X/Y · 右 Z/W 条"。
解决办法：调大 **设置 → 单次对比上限**；或者分批做——生成计划时在"只处理某个子目录"里填一个子树，缩小每次处理的范围。

**Q15：为什么"快速传输"也号称安全？**
因为它只省掉"删源前量一次大小"这一步，**源文件照样进回收站**。最坏结果是"目标那份可能不完整，源还在回收站里"。
详见 [第 16 章](#16-传输模式标准-vs-快速)。

**Q16：手机上能用吗？**
界面是响应式的。用 `start.bat 0.0.0.0 8787` 启动后，手机浏览器访问 `http://电脑IP:8787` 即可（同一局域网）。
注意：手机能看、能听、能操作，但**所有文件读写都发生在跑服务的那台电脑上**。

**Q17：改了设置怎么没生效？**
两件事：① 设置页改完要点 **「保存设置」**（否则只是填在框里）；② 如果你改的是 `config.toml` 文件本身，
要点顶栏 **「重载配置」** 或设置页的 **「从文件重载配置」**。

**Q18：候选区里为什么加不进那个 `.jpg`？**
候选区只收音频。加入非音频文件会被跳过并提示"候选区只收音频"。

## 19. 排错

### 19.1 日志在哪

| 位置 | 内容 |
| --- | --- |
| `%USERPROFILE%\.music-sync-hub\logs\msh.log` | 完整的后台日志（单个文件 4 MB 自动轮转，保留 3 个历史文件） |
| 界面 → **设置 → 后台日志** | 同一个日志的尾部，可直接看、按级别过滤、复制全部 |
| 界面 → **操作记录** | 每次执行的逐文件结果（业务层，比日志更贴近"我点了什么、结果如何"） |
| 启动窗口（黑窗口） | 启动信息与未捕获异常的简要输出；窗口一关就没了 |

日志文件的实际路径也会显示在「设置 → 后台日志」的标题下方。

### 19.2 界面上哪里看日志

**设置 → 后台日志** 这一块里有：

- **「刷新」**：重新读取；
- 级别下拉：**全部级别 / 只看 ERROR / 只看 WARNING / 只看 INFO**；
- **「清空（便于复现）」**：清掉**内存**里的日志缓冲（**日志文件保留**）。用法是"先清一下，再去复现问题"，之后看到的就全是这次操作的记录；
- **「复制全部」**：把当前显示的日志复制到剪贴板（浏览器不允许自动复制时会提示你手动选中）；
- 这一行的末尾会显示"共 N 行"（按级别过滤时会注明"已过滤 ERROR"之类）。

### 19.3 常见报错与含义

| 提示 | 含义 / 该怎么办 |
| --- | --- |
| **已有任务在执行：xxx（12/30）** | 同一时刻只允许一个写操作。等它结束，或去任务中心取消它。（HTTP 409） |
| **这个数据源是只读的，不能作为传输目标** | 目标数据源勾了"只读"。要写入就先去取消只读。 |
| **目标已存在，跳过** | 同名冲突策略是"跳过"（默认）。这是**正常结果，不是错误**，你的文件没被动过。 |
| **源文件不存在（可能已被移动）** | 索引里的记录已经过期：文件在工具外面被挪走/删了。重新扫描该数据源。 |
| **文件被占用或权限不足** | 文件被别的程序锁着，或当前用户没权限。关掉占用它的程序后，用操作记录里的「重试」按钮重试。 |
| **磁盘空间不足** | 目标盘满了。清一点空间再重试。 |
| **操作超时（已跳过）** | 这个文件卡住了（坏扇区、网络盘掉线、被独占），工具跳过它继续做别的。可以之后重试。 |
| **路径超出数据源根目录，已拒绝移动** | 目标路径算出来跑到库根目录外面了。工具宁可不做也不会碰根外的文件。检查你填的目标目录。 |
| **心跳停止** | 任务的后台线程已经不在（可能被强杀）。确认没在跑就取消它，释放独占位。 |
| **离线：路径不存在 / 根路径是文件，不是目录** | 数据源配置有问题：路径写错了、盘没插、网络位置没连上，或把文件路径当成了目录。 |
| **连接失败 + 排查提示** | 「测试连接」失败。先看提示里的具体原因（路径/认证/端口），网络源参考 [第 5 章](#5-数据源)的两条建议。 |
| **设置不合法：xxx 不能大于 yyy** | 设置值超出允许范围，被拦下了。按提示改到范围内。 |
| **部分设置未保存** | 有些值是合法的、有些不合法。合法的已保存，不合法的保持原样并列在弹窗里。 |
| **已有 N 个任务心跳停止（可能已中断）** | 见"心跳停止"。 |
| **暂存区里有 N 个非音频文件** | 它们不会入库，只占磁盘。去「中转站 → 上传暂存区」看是哪些，或删掉那个批次。 |
| **中转站空间不足** | 中转站已达上限。清理它，或把 `station_max_gb` 调大（填 0 不限额）。 |

### 19.4 界面打不开

1. 看那个黑窗口还在不在。如果已经退出，窗口里会有报错（启动失败会 `pause` 停住让你看）。
2. 确认你访问的是窗口里打印的地址（默认 `http://127.0.0.1:8787`）。
3. 端口被别的程序占了就换一个：`start.bat 127.0.0.1 9000`。
4. 想让别的机器访问，必须监听 `0.0.0.0`（`start.bat 0.0.0.0 8787`），并放行防火墙。
5. 想看服务是否活着：浏览器打开 `http://127.0.0.1:8787/api/system`，返回一段 JSON 就说明服务是好的（问题在前端/浏览器缓存）。

## 20. 已知限制

以下是**能确证**的限制，不是"以后会改"的承诺——请按现状使用。

1. **Windows 是主要平台。** 磁盘类型识别（可移除 / 慢速 / 网络位置判断）、读速实测、便携设备探测都只做了 Windows 实现；
   其它平台这些提示不会出现，只能手动勾"慢速盘模式"和"只读"。

2. **所有网络协议都是"实验性"。** SFTP / WebDAV / HTTP / SMB / FTP **只做完了代码实现，没有对着真实服务器完整验证过**
   （每个类型都写明了"没验证到什么程度"）。用它们时请先勾只读、先用小目录试。
   HTTP 目录源天生**只读**（后端会拒绝一切写入）。

3. **部分格式不能编辑标签。** 支持：`.flac`、`.mp3`、`.wav`、`.aiff/.aif`、`.m4a/.mp4/.m4b/.aac`、`.ogg/.oga`、`.opus`、`.wv`、`.tta`。
   **不支持**：`.wma`、`.mka`、`.caf`、`.ape`、`.dsf`、`.dff`、`.mpc` 等（会提示"这种格式暂不支持改标签"）。
   它们的扫描、整理、播放仍然正常。

4. **MTP / 便携设备只探测，不支持读写。** 原因是它需要 Windows 便携设备 COM 接口或 libmtp，而本项目只依赖标准库 + 少数纯 Python 包。
   替代方案：把设备的 USB 模式切成"文件传输/U 盘模式"当本地盘用，或先用厂商工具拷到本地目录。

5. **试听依赖浏览器解码能力。** 服务端只做分段转发、**不转码**。浏览器解不了的格式（常见如 `.ape`、`.wv`、`.wma`、`.dsf`）点了不会响。

6. **单次对比 / 查重有上限截断。** 默认每侧 8000 条（`max_compare_tracks`），超出会被截断并在界面上给出橙色提示；
   超大库建议按目录分批。

7. **一次只能跑一个写操作。** 不排队（排队会基于过期的文件状态操作）。预演不受限。

8. **回收站的还原只支持本地 / 映射盘数据源。** 文件浏览 →「回收站」可以一键还原回原目录；网络源（SFTP/WebDAV/SMB…）的删除语义由各自适配器决定，暂不提供统一的还原入口。

9. **非音频文件不纳管。** 不在列表里显示、不能勾选/移动/改标签/进候选区/跨库传输，只在特定位置被"列出来提醒"。
   详见 [7.8](#78-非音乐文件能做什么不能做什么)。

10. **版本标记是按文本关键词识别的。** "伴奏 / 重制版 / 现场版 / 翻唱 / Remix / 简繁…"这些标记来自**文件名与标题里的关键词**匹配，
    识别不到的就会被当成同一版本。所以文件名太随意时，"区分不同版本"的效果会打折扣。

11. **网络源的高级连接参数只能改配置文件。** 界面提供的是"主机 + 端口 + 用户名 + 密码 + 远端根路径"这套基本项；
    SFTP 的私钥认证（`extras.key_file` / `extras.key_passphrase_ref` / `look_for_keys` / `allow_agent`）、
    FTP 的 FTPS 开关（`extras.tls`）、超时（`extras.timeout`）等需要手改 `config.toml` 后点「重载配置」。

12. **"覆盖"和"永久删除"真的不可恢复。** 见 [第 17 章](#17-文件安全你能指望什么)末尾那四条。

13. **界面偏好存在浏览器里。** 换浏览器、换设备、清浏览器数据，这些"上次怎么看的"就没了（不影响任何文件和设置）。
    候选区的内容也一样存在浏览器里。
