## 第 17 轮 · 对新写的代码本身再审计

**方法**：把今天新加/改动的几处代码（`proclock`、`inside_root_real`、
`in_source_rel`、`_init_schema` 的损坏恢复、`state_meta`、`cleanup_stale_parts`、
`browse` 排序修复）当成"陌生代码"做对抗测试 —— 新代码最容易带新 bug。

| 检查 | 结果 |
| --- | --- |
| **`proclock.release()` 未持锁时会不会删别人的锁** | **★ 会（已修）** |
| 错误 token 会不会删自己的锁 | 不会 ✓ |
| 无参 `release()` 用自身 token | 正常 ✓ |
| `inside_root_real` 根本身 / 根内文件 / 根内不存在 / 根外 / 带 `..` | 5/5 正确 ✓ |
| `in_source_rel` 空 / 相对 / 前导斜杠 / 绝对=根 / 绝对=根内 | 4/5 —— 前导斜杠 `/sub/a.mp3` 被拒（**安全设计**，见下） |
| 盘符相对路径 `C:Windows` | 当普通相对路径，不越界 ✓ |
| 损坏库 + 文件被占用（改名失败） | 以前只抛原始 sqlite 错误 → **已改为可照做的指引** |

### 修掉的 bug（本轮最重要）

```python
# proclock.release() 原来写的是：
if tok and tok not in holder:
    return
p.unlink()          # ← tok 为 None 时条件为假，直接删了**别人的**锁
```

**触发场景很真实**：进程重启 → 用户点「恢复未完成任务」→ `Jobs.finish()`
调 `proclock.release()` → 本进程并没有持锁，却把**另一个正在运行的实例**的
锁删了 → 两个进程同时写文件，跨进程互斥形同虚设。

修法：`if not tok: return`（没持锁就什么都不做），并且只删 token 匹配的锁。
回归测试见 `tests/test_hardening_round6.py::test_release_without_holding_is_noop`。

### 前导斜杠被拒：不是 bug

`in_source_rel("/sub/a.mp3")` 返回 400。在 Windows 上 `/sub/a.mp3` 是
**盘符相对路径**（相对当前盘的当前目录），不是"数据源根下的 sub"。
拒绝比猜测安全；前端一直传相对路径（`sub/a.mp3`）或不带斜杠的绝对路径。

## 第 19 轮 · 用户反馈的两个交互 bug + 文档规范

这一轮由用户实机使用反馈驱动（不是自动探针），修完都做了**真实浏览器验证**。

### Bug A：点一首歌，把这首歌之前的全加进播放列表

- **原因**：曲库行首的播放按钮调 `playFrom()`，而它把 `data.tracks`
  **整批**塞进队列（`App.playList(list, t.id, '曲库')`）。于是点第 50 首，
  队列里是 1..50 —— 用户看到"播放列表里出现这首歌之前的全部曲目"。
- **修法**：`playFrom()` 改成 `App.playTrack(t)`，**点哪首放哪首**。
  另加两个显式入口：
  - 曲库 / 文件浏览 **行尾 ＋**：追加到播放列表（不打断当前播放）
  - 曲库工具栏 **「全部入队」**：整列表入队（保留旧能力，但改成显式操作）
- **验证**：真实浏览器点第 5 行播放 → `queue.items.length === 1`；
  点 ＋ → 2；点「全部入队」→ 300。文件浏览每行都有 ＋（300 个）。

### Bug B：候选区的智能整理"一下就整理了"

- **原因**：`smartAssign()` 把 `group_by='artist_album'`、`min_group=5`
  **写死**，点一下就直接填好去向 —— 既没有选项，也没有预览。
  另外它传的 `keep_flat_below` **接口根本不读**（接口读的是 `structure`），
  等于"分层/单层"永远是默认值。
- **修法**：改成三段式
  1. **选项**：分组依据（作者+专辑/仅作者/仅专辑）、目录结构（分层/单层）、
     最少同组（1–100）
  2. **预览**：列出"去向目录 → 文件数"，确认后才写
  3. **采用**：只写去向（分颜色），**不移动文件**；执行仍由「执行移动」动手
- **验证**：临时库（6 首带标签）→ 选项框（3 组/2 结构/最少同组）→
  预览显示"4 个文件 → 2 个目录"→ 采用后去向列出现两组。
