# Music Sync Hub · 跨服务器音乐库管理器

两台服务器（一台 Windows、一台 Linux）各跑着不同的音乐服务，音乐文件在 Windows 上单向备份到 Linux，
但两边的**元数据写法不一样**（一边有音轨号前缀、一边没有；标签编码/语言不同），
所以直接用 rsync / 镜像工具会互相打架，还敢直接删文件。

这个工具就是为这种场景做的：**双栏对照着看，查漏、查重、补齐，全程由你决定，绝不自动删。**

```
┌────────────── 左：Windows 音乐库 ──────────────┬────────────── 右：Linux 音乐库 ──────────────┐
│ ✅ 01 - 周杰伦 - 晴天.wav    2.5MB 无损 310k   │ ✅ 01 - 周杰伦 - 晴天.wav    2.5MB 无损 310k   │
│ ⚠ Queen - Bohemian Rhapsody 4.1MB ← 右库没有    │ —                                              │
│ ✅ Get Lucky.wav             8.0MB 320k        │ ✅ Get Lucky.flac           30MB 无损 ← 更好    │
└────────────────────────────────────────────────┴────────────────────────────────────────────────┘
                    匹配依据：文件名 + 时长 + 内容哈希（不依赖标签是否一致）
```

> **第一次用？** 直接看 [QUICKSTART.md](QUICKSTART.md) —— 5 分钟从启动到跑通。
> **想完整了解每个按钮？** [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md)（用户手册）。
> **想看代码怎么组织？** [`docs/TECHNICAL.md`](docs/TECHNICAL.md)（技术文档）。

## 三条最重要的保证

这套工具会碰到你的音乐文件，所以先把底线说清楚：

1. **绝不覆盖**。目标已存在就停下来问你（跳过 / 改名 / 覆盖），默认不覆盖。
2. **删除进回收站**。所有删除都移到 `<库根>/.music-sync-trash/日期/`，可恢复。
   永久删除需要单独显式勾选。
3. **搬运是"复制 → 校验 → 删源"**，校验没通过就不删源文件。

完整清单见 [docs/USER_GUIDE.md 第 17 章](docs/USER_GUIDE.md)。

## 一、它能做什么

| 能力 | 说明 |
| --- | --- |
| **双栏对照浏览** | 左右各选一个库，一目了然地看两边差异：已配对 / 仅左侧 / 仅右侧 / 需人工确认 |
| **完整歌曲信息** | 文件名、封面、标题、作者、专辑、格式、码率、采样率、位深、声道、时长、体积、音质分、抽样哈希 |
| **在线试听** | 浏览器里直接播放任意一侧的文件（HTTP Range 流式读取，可拖进度条），对比两边音质差别 |
| **查漏补齐** | 精确算出"哪边少了哪些文件"，生成复制计划；**默认只预演不写入**，你勾选后才执行 |
| **断点续传** | 大文件传到一半断了（拔线/休眠/网络抖动），下次接着传，不用从头再来；带源校验，不会拼错内容 |
| **查重** | 同库内 / 跨库查重；按"内容哈希"把同名文件分成"完全一致的副本"和"只是同名不同音质"两类 |
| **保留谁由你定** | 每组给出音质推荐（无损 > 高码率 > 采样率 > 位深），也可以按体积/时间，或逐个自己挑 |
| **安全删除** | 删除一律先移入 `<库根>/.music-sync-trash/日期/`，可随时恢复；永久删除需显式勾选 |
| **回收站还原** | 删除时会记下**原位置**；文件浏览 →「回收站」可一键还原回原目录（同名跳过/改名，绝不覆盖） |
| **改名统一** | 同一首歌两边文件名不同时，可选把一侧改成另一侧的名字 |
| **数据源** | 本地磁盘 / 已挂载盘符 / SFTP / WebDAV / HTTP 目录 / SMB / FTP |

> 网络类数据源（SFTP / WebDAV / HTTP 目录 / SMB / FTP）目前标为 **实验性** ——
> 代码路径完整，但**没有对真实服务器做过完整验证**。界面上会显示警告标记。

## 二、快速开始

### 1. 安装

只需要 [uv](https://docs.astral.sh/uv/)（它会自动准备 Python 环境）：

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

### 2. 启动

```bash
# macOS / Linux
bash start.sh                 # 打开 http://127.0.0.1:8787
bash start.sh 0.0.0.0 9000    # 想让别的机器访问就用这个

# Windows：双击 start.bat，或
start.bat 0.0.0.0 8787
```

打开浏览器访问提示里的地址即可。界面完全离线，不依赖任何外部服务。

### 3. 添加你的两台服务器

点左上角 **「+ 添加数据源」**，按情况选类型：

| 场景 | 该选什么 | 怎么填 |
| --- | --- | --- |
| 音乐在运行本机的磁盘上 | 本地 / 已挂载盘符 | Windows 写 `D:\Music`；Linux 写 `/mnt/music` |

填完点 **「🔌 测试连接」** 确认能读到文件，再点 **「⟳ 扫描」** 建索引。

> **强烈建议**把作为"源"的那一侧勾上 **「只读」**——这样任何写操作都会被直接拒绝，多一道保险。

### 4. 开始使用

1. **曲库浏览**：看每台机器上的文件、封面、码率时长，点 ▶ 试听。
2. **双栏对比**：左右各选一个库 → 点「开始对比」→ 看差异。
   - 点任意一行可看**配对详情**：两边各自的封面、参数、音质分，以及为什么判定它们是一首歌。
3. **生成同步计划**：选好方向（左➜右 / 右➜左 / 双向），点「🧪 预演」确认无误，再执行。
4. **查重**：选范围（单库 / 跨库）→「开始查重」→ 界面会把重复分成两组：
   - 🟥 **内容完全一致**：字节相同，可以安全删掉多余的
   - 🟨 **同名但内容不同**：不同音质/版本，**不会自动勾选**，需要你自己决定留哪份
5. **操作记录**：每次执行都留痕，能看到每个文件的结果和回收站路径。

## 三、匹配算法（为什么不需要两边元数据一致）

同一首歌的判定是一条**证据链**，按优先级递进：

```
① 归一化文件名完全相同     ← 最强证据
   去掉 "01 -"、"(320k)"、"[FLAC]"、"_HQ" 等噪声后比较
② 歌键相同（标题 + 主艺术家 + 时长桶）
   补文件名被改写的情况
③ 模糊兜底（时长邻近 + 门禁）
   文件名不够像时，必须"艺术家一致 + 时长几乎相同"
④ 内容哈希（抽样/全量）
   头尾各取一段做 SHA1；小文件直接全量；哈希相同 → 判定为同一份文件
```

综合打分权重：文件名 38% · 时长 34% · 标签 16% · 体积 12%。

**专门防误判的几条规则**（都是实测踩出来的坑）：

- **时长差超过 2×容差** → 判为不同版本（现场版 / 剪辑版 / 伴奏），不自动配对
- **艺术家明显不一致** → 一票否决。比如 `Windows Only - Exclusive Track`
  和 `Linux Only - Exclusive Track`，文件名相似度 0.85、标题都一样，只有艺术家能揭穿它
- **同名不同音质**：`Daft Punk - Get Lucky.wav` 和 `(低音质).wav` 会被归到**同一个"相似组"**
  的**不同内容子簇**，永远不会被自动一起删

**查重的哈希策略**（省流量的关键）：

| 情况 | 处理 |
| --- | --- |
| 体积在组里是独一份 | 跳过哈希（不可能是别人的副本） |
| 体积占多数 | 只哈希体积相同的那些 |
| 文件 ≤ 6MB | 一次读完，全量哈希（抽样会漏掉中间字节） |
| 文件 > 6MB | 头尾各取 256KB 抽样；需要更严可选「全量哈希」 |

## 四、安全设计

| 机制 | 行为 |
| --- | --- |
| **默认预演** | 不点执行，任何写操作都不会碰文件；「🧪 预演」只做安全检查并列出结论 |
| **显式确认** | 写操作必须带 `confirm`，删除前弹窗列出数量与体积 |
| **先临时后改名** | 写入落成 `xxx.mshpart` 再原子改名 —— 断网/断电不会留半截文件 |
| **回收站** | 删除 = 移动到 `<源根>/.music-sync-trash/YYYYMMDD/`，界面上会给出路径 |
| **只读熔断** | 数据源勾了「只读」，任何写入/删除都会被拒绝并标记为"阻断" |
| **复制校验** | 复制后比对字节数，可选抽样哈希比对；不一致立即报错 |
| **冲突策略** | 目标已存在时可选 跳过（默认）/ 覆盖 / 自动改名 `(2)` |
| **失败隔离** | 单个文件失败不影响其它步骤，逐条记录原因 |

## 五、配置文件

配置在 `~/.music-sync-hub/config.toml`（Windows 是 `%USERPROFILE%\.music-sync-hub\config.toml`）。
界面上也可以直接改，改完点「重载配置」即可生效。

```toml
[[sources]]
id = "linux"
name = "本地音乐库"
type = "local"
root = "D:\\Music"                  # 本机路径；Windows 写 D:\Music，Linux/macOS 写 /mnt/music
read_only = false

[settings]
scan_workers = 8                    # 扫描并发
hash_size_limit_mb = 512            # 超过这个体积只做抽样哈希
quick_hash_probe_kb = 256           # 抽样哈希头尾各取多少 KB
duration_tolerance_sec = 2.0        # 时长容差（秒）
name_similarity = 0.86              # 模糊匹配阈值
default_keep_policy = "best_quality"
trash_dir = ""                      # 留空 = 各库根目录下的 .music-sync-trash
```

> Windows 上的本机路径请写 `D:\Music` 或 `D:/Music`；也支持 `/d/Music`
> 这种 Git-Bash 风格，会按盘符自动识别。

## 六、界面风格

界面是 **Windows 10 磁贴（Metro / Live Tile）** 风格：

- **纯平直角**：没有圆角、没有渐变，只有磁贴悬停时微微抬起
- **磁贴墙**：每个数据源是一块 Win10 标准色磁贴（蓝 / 青 / 紫 / 橙 / 绿…按 id 稳定分配），
  显示类型图标、路径、曲目数、上次扫描时间；鼠标移上去右上角浮出「测试连接 / 扫描 / 浏览 / 编辑 / 删除」
- **Segoe UI** 字体族，中文自动回落到微软雅黑 UI / 苹方
- **主题色 #0078D7**，选中项用 3px 主题色指示条（导航项在左侧，顶部标签在下方）
- **白色 2px 聚焦框**：键盘 Tab 导航时和 Win10 一致
- 图标全部是内联 SVG（Metro 线性/实心字形），不依赖任何外部字体或 CDN

> 前端是原生 HTML/CSS/JS，不需要构建。静态资源带 `?v=` 版本号，
> 改完样式/脚本后把 `index.html` 里的版本号 +1 即可让浏览器立即取到新文件。

## 八、常见问题

**Q：双击 `start.bat` 没反应 / 打不开界面？**

先直接访问 <http://127.0.0.1:8787/> —— 很可能服务已经在跑（`start.bat` 会探测到并
自动打开浏览器，不再起第二个实例）。如果窗口停住并报了原因，按提示换端口
（`start.bat 127.0.0.1 8899`）或先 `uv sync`。

**Q：两边标签完全不一样，会不会配不上？**
A：不会。匹配的主证据是**文件名归一化 + 时长 + 内容哈希**，标签只是加分项。
两边一边写 `01 - 周杰伦 - 晴天.wav`、一边写 `周杰伦 - 晴天.wav`，也能配上。

**Q：会不会把我不同的两首歌误判成一首？**
A：几条规则专门防这个：时长差太大不配、艺术家明显冲突不配、置信度中低的会标成
「需人工确认」（紫色），配对详情里能看到完整判定依据和两边参数，可以分别试听后决定。

**Q：查重会不会直接把我的文件删了？**
A：不会。删除必须你手动点、手动确认，而且是**移入回收站**。
「同名但内容不同」的音质版本压根不会被自动勾选。

**Q：几百 GB / 几万个文件会不会很慢？**
A：扫描是增量的（大小/修改时间没变就直接用索引），并发可调；
大文件只读头部解析标签，不整份下载；查重只哈希"体积占多数"的那一档。

**Q：能在手机上用吗？**
A：可以，界面是响应式的。用 `start.sh 0.0.0.0 8787` 启动后，手机浏览器访问 `http://电脑IP:8787` 即可。
